## Обзор архитектуры
**M68k** (учебная упрощённая) — 32‑битная CISC‑подобная архитектура, вдохновлённая семейством Motorola 68000.

Особенности:
- 8 **регистров данных** `D0–D7`.
- 8 **адресных регистров** `A0–A7` (где `A7` — стековый указатель, **SP**).
- Богатые **режимы адресации** и гибкая работа с памятью.
- Разнообразные **размеры операндов** (байт `.b`, длинное слово `.l`).
- **Статусный регистр** (флаги условий).
- **MMIO** (память‑отображённый ввод‑вывод).

> Комментарии в ассемблере начинаются с `;`.

---

## Регистры и статусный регистр
- **D0–D7** — общие регистры для арифметики, логики, манипуляций с данными.
- **A0–A7** — адресные регистры, используются для адресации/указателей. `A7` играет роль **SP** (указателя стека).
- **PC** — счётчик команд.
- **SR** — статусный регистр (флаги условий):
  - **N** (Negative) — результат отрицательный.
  - **Z** (Zero) — результат равен нулю.
  - **V** (Overflow) — арифметическое переполнение.
  - **C** (Carry) — перенос/заём в арифметике.

> Примечание: классический 68000 имеет также флаг **X (Extend)** и ряд системных битов в SR. В данной упрощённой ISA рассматриваются только **N, Z, V, C**.

## Размеры операций и «ByteSize»
Инструкции могут работать с разными размерами данных:
- **`.b`** — байт (8‑бит).
- **`.l`** — «long» (32‑бит, значение по умолчанию).

**Правила ByteSize (упрощённая модель):**
- Байтовые операции используют **1 байт** данных.
- Длинные операции используют **4 байта** данных.
- Все **прыжки и ветвления** кодируются **длинным (6‑байтовым)** форматом **независимо** от смещения.

Пример: `add.b D0, D1` воздействует только на **младший байт** регистра `D1` (и выставляет флаги по байтовому результату), а `add.l` — на все 32 бита.

## Режимы адресации
Нотация источника/приёмника как в синтаксисе M68k.

### Регистровая
- **Data Register Direct**: `D0 … D7`
- **Address Register Direct**: `A0 … A7`
- **Immediate**: непосредственное значение
  - Пример: `move.l 42, D0`

### Память
- **(An)** — косвенно через адресный регистр:
  - `move.l (A0), D0`
- **(An)+** — пост‑инкремент адреса:
  - `move.l (A0)+, D0`  ; после чтения `A0 += size`
- **-(An)** — пред‑декремент адреса:
  - `move.l -(A0), D0`  ; перед чтением `A0 -= size`
- **d(An)** — смещение 16‑бит со знаком:
  - `move.l 8(A0), D0`, `move.l -4(A0), D0`
- **d(An, Xn)** — индексный: база `An` + индекс `Xn` (D* или A*) + смещение `d`:
  - `move.l 4(A0, D1), D0`, `move.l 8(A0, A1), D0`

> *Подсказка:* размер шага в `(An)+` и `-(An)` равен размеру операции: 1 для `.b`, 4 для `.l`. Для `A7` некоторые реализации 68000 делают особую обработку байтовых доступов (выравнивание стека на слово). В упрощённой ISA обычно используется единый шаг — проверяйте свою среду.

## Набор инструкций
Ниже — синтаксис, краткое описание и семантика (упрощённая модель).

### Перемещение данных
**Move**
```
move.<size> <src>, <dst>
; <dst> ← <src>
```
Примеры:
```
move.l D0, D1
move.b D0, D1
move.l 42, D0
move.l (A0), D0
move.l D0, (A1)
move.l (A0)+, D0
move.l -(A0), D0
move.l 8(A0), D0
move.l -4(A0), D0
move.l 8(A0, D1), D0
move.l 4(A0, A1), D0
```

**Move to Address Register**
```
movea.l <src>, <Adst>
; <Adst> ← <src>
```
Примеры:
```
movea.l 1000, A0
movea.l D0, A1
```

### Логические операции
**NOT**
```
not.<size> <dst>      ; <dst> ← ~<dst>
```
Примеры: `not.l D0`, `not.b D0`

**AND**
```
and.<size> <src>, <dst>  ; <dst> ← <dst> & <src>
```
Примеры: `and.l D0, D1`, `and.b D0, D1`

**OR**
```
or.<size> <src>, <dst>   ; <dst> ← <dst> | <src>
```
Примеры: `or.l D0, D1`, `or.b D0, D1`

**XOR**
```
xor.<size> <src>, <dst>  ; <dst> ← <dst> ^ <src>
```
Примеры: `xor.l D0, D1`, `xor.b D0, D1`

### Арифметика
**ADD**
```
add.<size> <src>, <dst>  ; <dst> ← <dst> + <src>
```
Примеры: `add.l D0, D1`, `add.b D0, D1`, `add.l 10, D0`, `add.b 5, D0`

**SUB**
```
sub.<size> <src>, <dst>  ; <dst> ← <dst> - <src>
```
Примеры: `sub.l D0, D1`, `sub.b D0, D1`, `sub.l 1, D0`, `sub.b 1, D0`

**CMP** (сравнение, только флаги)
```
cmp.<size> <src>, <dst> ; temp ← <dst> - <src> ; флаги по temp
```
Примеры: `cmp.l D0, D1`, `cmp.b D0, D1`, `cmp.l 10, D0`, `cmp.l (A0), D0`

**MUL**
```
mul.<size> <src>, <dst> ; <dst> ← <dst> * <src>
```
Примеры: `mul.l D0, D1`, `mul.b D0, D1`

**DIV**
```
div.<size> <src>, <dst> ; <dst> ← <dst> / <src>
```
Примеры: `div.l D0, D1`, `div.b D0, D1`

> Деление на ноль — поведение определяется реализацией (исключение/фиксированное значение). Уточняйте для вашей среды.

### Сдвиги и вращения
**ASL** — арифм. влево, **ASR** — арифм. вправо (с сохранением знака);
**LSL/LSR** — логические сдвиги (вправо — заполнение нулями).
```
asl.<size> <count>, <dst>
asr.<size> <count>, <dst>
lsl.<size> <count>, <dst>
lsr.<size> <count>, <dst>
```
Примеры: `asl.l 2, D0`, `asr.b 2, D0`, `lsl.l D1, D0`, `lsr.l 2, D0`

### Передача управления
**JMP**
```
jmp <label>     ; PC ← <label>
```

**Ветвления по флагам**
```
bcc/bcs/beq/bne/blt/bgt/ble/bge/bmi/bpl/bvc/bvs <label>
```
Семантика:
- `bcc` — если `C==0`.
- `bcs` — если `C==1`.
- `beq` — если `Z==1`.
- `bne` — если `Z==0`.
- `blt` — если `N != V`.
- `bgt` — если `Z==0` и `N==V`.
- `ble` — если `Z==1` или `N!=V`.
- `bge` — если `N==V`.
- `bmi` — если `N==1`.
- `bpl` — если `N==0`.
- `bvc` — если `V==0`.
- `bvs` — если `V==1`.

**JSR/RTS** — вызов/возврат
```
jsr <label>      ; сохранить адрес возврата в стеке, перейти к подпрограмме
rts              ; извлечь адрес из стека и вернуться
```

### Кадр стека: link/unlk
**LINK** — создание кадра функции
```
link <Afp>, <offset>
```
Операции:
1) Поместить текущее значение `<Afp>` (обычно `A6`) в стек.
2) Скопировать `SP (A7)` в `<Afp>` — новый frame pointer.
3) Прибавить `offset` к `SP` для выделения локальных (обычно отрицательное значение, напр. `-8`).

Доступ:
- Локальные переменные: **отрицательные** смещения от `A6`: `-4(A6)`, `-8(A6)`.
- Аргументы, переданные через стек: **положительные** смещения, напр. `8(A6)`.

**UNLK** — разрушение кадра
```
unlk <Afp>     ; SP ← Afp ; pop в Afp старого кадра
rts
```

**Полный пример:**
```
my_function:
    link A6, -12
    move.l 8(A6), D0     ; параметр из стека
    move.l D0, -4(A6)    ; локальная переменная
    ; ... тело функции ...
    unlk A6
    rts
```

### Остановка
```
halt      ; остановка машины/эмулятора
```

## Просмотр состояния (State Views)
Учебные среды могут поддерживать быстрый просмотр значений:
- `D<n>:dec`, `D<n>:hex` — регистры данных `D0–D7`.
- `A<n>:dec`, `A<n>:hex` — адресные регистры `A0–A7`.
- `PC:dec`, `PC:hex` — счётчик команд.
- `SR:bin` — статусный регистр (флаги `N,Z,V,C`).

## Идиомы и шаблоны
- **Очистка младшего байта:** `and.l 255, D0`  ; эквивалент zero‑extend после `move.b`.
- **Знаковое расширение байта в 32 бита:** `extb ->` (в упрощённой ISA нет `ext`, используйте `asl/asr` над младшим байтом или арифметику).
- **Инкремент указателя на размер элемента:** `add.l 4, A0` для int32; либо используйте `(A0)+`/`-(A0)`.
- **Push/Pop (эмуляция):**
  - `move.l D0, -(A7)` ; push D0
  - `move.l (A7)+, D0` ; pop D0
- **Вызов функции:** `jsr target` → результат в `D0` (де‑факто соглашение для примеров ниже).
- **Перебор массива:** адрес в `A0`, счётчик в `D1`, аккумулятор в `D0`.

> Подсказка: операции `.b` изменяют **только** младший байт регистра‑назначения; старшие биты сохраняют прежнее значение. Если нужен чистый 8‑битный результат в 32‑битном представлении — выполните явное обнуление/расширение.

## Примеры

### Копирование памяти (post‑inc)
```asm
; memcpy: копирует N байт из A0 → A1
; Вход: A0=src, A1=dst, D1=N (байт)
; Не разрушаем: A6, A7
memcpy_b:
    tst:    cmp.l 0, D1          ; Z=1 если N==0
    beq     .done
    move.b  (A0)+, D0           ; D0 ← *A0; A0+=1
    move.b  D0, (A1)+           ; *A1 ← D0; A1+=1
    sub.l   1, D1
    bne     memcpy_b
.done:
    rts
```

### Подсчёт длины строки (байтовый цикл)
```asm
; strlen: считает длину строки до '\0'
; Вход: A0=ptr, Выход: D0=len
strlen:
    move.l 0, D0
.loop:
    move.b (A0)+, D1
    cmp.b  0, D1
    beq    .done
    add.l  1, D0
    bra    .loop
.done:
    rts
```

### Вызов функции, кадр и локальные
```asm
; sum_array_long: сумма N элементов int32 по адресу A0
; Вход: A0=ptr, D1=N; Выход: D0=sum
sum_array_long:
    link    A6, -8
    move.l  0, D0          ; acc=0
    move.l  A0, -4(A6)     ; сохранить ptr
    move.l  D1, -8(A6)     ; сохранить N
.loop:
    cmp.l   0, -8(A6)
    beq     .done
    move.l  (-4)(A6), A1   ; A1 = ptr
    move.l  (A1), D2
    add.l   D2, D0
    add.l   4, A1
    move.l  A1, -4(A6)
    sub.l   1, -8(A6)
    bra     .loop
.done:
    unlk    A6
    rts
```

## Таблица условий ветвлений
| Мнемоника | Условие на флаги | Интерпретация |
|---|---|---|
| `bcc` | `C==0` | без переноса |
| `bcs` | `C==1` | перенос установлен |
| `beq` | `Z==1` | равно нулю |
| `bne` | `Z==0` | не равно |
| `bmi` | `N==1` | отрицательно |
| `bpl` | `N==0` | положит./ноль |
| `bvs` | `V==1` | переполнение |
| `bvc` | `V==0` | без переполнения |
| `bge` | `N==V` | ≥ (знаковое) |
| `blt` | `N!=V` | < (знаковое) |
| `bgt` | `Z==0 && N==V` | > (знаковое) |
| `ble` | `Z==1 || N!=V` | ≤ (знаковое) |

## Советы и типичные ошибки
1. **Сохранение старших бит при `.b`.** После `move.b`/`add.b` старшие 24 бита регистра не обнуляются — расширяйте результат вручную при необходимости.
2. **Шаг `(An)+`/`-(An)`.** Убедитесь, что шаг равен размеру операции (1 для `.b`, 4 для `.l`). Для `A7` возможны особенности реализаций (выравнивание).
3. **Смешивание знаковых/беззнаковых сравнений.** Семантика `N,V,Z,C` относится к знаковым операциям; проверяйте корректность ветвлений.
4. **Деление на ноль.** Уточните поведение в вашей среде.
5. **Доступ к MMIO.** Остерегайтесь побочных эффектов: повторное чтение одного адреса может иметь последствия.
6. **Кадр функции.** Не забывайте парами `link A6, …` и `unlk A6` + `rts`.

## Частые вопросы (FAQ)
**Q: Как загрузить адрес/немедленное 32‑битное значение?**
> `move.l <imm32>, Dn` или `movea.l <imm32>, An` (в упрощённой ISA это допустимо).

**Q: Какие смещения доступны в `d(An)`?**
> Знаковое 16‑бит смещение (`-32768 … +32767`) — согласно упрощённой модели.

**Q: Как читать/писать по адресу и сразу двигать указатель?**
> Используйте `(An)+` (post‑inc) и `-(An)` (pre‑dec). Это удобно для стековых операций и копирования.

**Q: Всегда ли ветвления кодируются одинаково?**
> В данной модели — да: все переходы и ветвления имеют длинную (6‑байт) форму.

**Q: Где хранить результат функции?**
> Для простоты примеров — в `D0`. Если договоритесь иначе, придерживайтесь выбранного соглашения во всём проекте.
