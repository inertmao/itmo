## Обзор архитектуры
**F32a** — 32‑битная стековая архитектура, вдохновлённая системами Forth и ядром F18a.

Особенности:
- Два основных стека: **стек данных** и **стек возвратов**.
- Два регистра общего назначения: **A** и **B**.
- Операции ориентированы на стек, что упрощает множество задач.
- **EAM** (Extended Arithmetic Mode) — расширенный режим для операций «с переносом» (carry‑in).
- Флаг переноса **C** для арифметики.
- Память‑отображённый ввод‑вывод (**MMIO**).

Комментарии в F32a‑ассемблере начинаются с обратного слэша `\` и действуют до конца строки.

> Вдохновлено: [F18a](https://www.greenarraychips.com/home/documents/greg/DB001-221113-F18a.pdf)

## Модель исполнения и обозначения стека
- **T** — верх стека данных (*Top*), **S** — второй элемент (*Second*).
- **R** — вершина стека возвратов (*Return top*).
- Запись эффектов на стек даётся в форто‑нотации: `( before -- after )`.
- Если не указано иное, операции берут операнды с вершины стека данных и кладут результат обратно на стек данных.

> Память и адресация: архитектура 32‑битная; конкретная единица адреса (байт/слово) зависит от реализации вашей среды. В примерах предполагается, что `@+`/`!+` инкрементируют `A` **на одну адресную единицу**; если память слово‑адресуемая — это следующий 32‑битный слот; если байтовая — следующий байт.

---

## Регистры, флаги и режим EAM
- **A, B** — регистры общего назначения. Часто `A` — базовый указатель для `@/!`, `B` — база для операций с `@b/!b`.
- **C (Carry)** — флаг переноса. Устанавливается инструкцией `+` (и сохраняется через `dup`). Большинство других инструкций **сбрасывают/теряют** флаг C (см. ниже).
- **EAM** — расширенный арифметический режим: если включён (ненулевое значение), `+` добавляет ещё и входящий перенос `C`.

**Поведение флагов:**
- По спецификации: «Most of the instructions drop the carry flag. Exceptions: `add`, `dup`.»
  - `+` — вычисляет перенос и обновляет `C` (и учитывает `C` как вход, если `EAM=1`).
  - `dup` — **не меняет** `C`.
  - Иные инструкции — трактуются как «обнуляют или делают C неопределённым»; рекомендация: не полагайтесь на `C` после них.

## Размер инструкций и операндов
- **Размер инструкции:** 1 байт опкода + по **4 байта** на каждый явный аргумент.
- Примеры: `lit <imm32>` — 1+4 байта; `@p <addr>`/`!p <addr>` — 1+4 байта; безоперандные инструкции — 1 байт.

---

## Просмотр состояния (State Views)
Поддерживаемые просмотры (в эмуляторе/отладчике):
- `A:dec`, `A:hex` — регистр **A**.
- `B:dec`, `B:hex` — регистр **B**.
- `T:dec`, `T:hex` — вершина стека данных.
- `S:dec`, `S:hex` — второй элемент стека данных.
- `R:dec`, `R:hex` — вершина стека возвратов.
- `stack:dec`, `stack:hex` — весь стек данных.
- `rstack:dec`, `rstack:hex` — весь стек возвратов.
- `EAM` — 1 если включён, иначе 0.
- `C` — флаг переноса: 1 установлен, 0 сброшен.

## Набор инструкций
Ниже приводятся синтаксис, смысл и эффекты на стек.

### Перемещение данных
- **Literal** — `lit <value>` — `( -- value )`  
  Положить немедленное 32‑битное значение на стек данных.

- **Fetch from Address** — `@p <address>` — `( -- mem[address] )`  
  Считать слово по абсолютному адресу и положить на стек.

- **Fetch** — `@` — `( -- mem[A] )`  
  Считать слово по адресу в `A`.

- **Fetch Plus** — `@+` — `( -- mem[A] )`, затем `A ← A + 1`  
  Считать по `A` и инкрементировать `A`.

- **Fetch B** — `@b` — `( -- mem[B] )`  
  Считать слово по адресу в `B`.

- **Store to Address** — `!p <address>` — `( x -- )`  
  Записать верх стека `x` по абсолютному адресу.

- **Store** — `!` — `( x -- )`  
  Записать `x` по адресу в `A`.

- **Store Plus** — `!+` — `( x -- )`, затем `A ← A + 1`  
  Записать по `A` и инкрементировать `A`.

- **Store B** — `!b` — `( x -- )`  
  Записать `x` по адресу в `B`.

- **A‑Store** — `a!` — `( x -- )`  
  `A ← x` (вынуть значение со стека в регистр `A`).

- **B‑Store** — `b!` — `( x -- )`  
  `B ← x`.

- **A‑Fetch** — `a` — `( -- A )`  
  Положить текущее значение регистра `A` на стек.

### Арифметика
- **Add** — `+` — `( a b -- sum )`  
  Сложить два верхних значения.
  - Без EAM: `sum = a + b`, `C` устанавливается по переносу из старшего бита.
  - При `EAM=1`: `sum = a + b + C_in`, где `C_in` — текущий перенос; затем `C` обновляется по результату.

- **Multiply Step** — `+*` — микрошаг умножения.  
  Семантика (согласно спецификации):
  ```
T ← T + ( if A[0] then S else 0 )
A ← A >> 1
A[31] ← (T[0] ? 1 : 0)
T ← T >> 1
  ```
  Используется итеративно (повторять 32 раза) для умножения «сдвиг‑сложение».

- **Divide Step** — `+/` — микрошаг **восстанавливающего деления**.  
  Роли:
  - **Dividend** — `A`
  - **Divisor** — `mem[B]`
  - **Partial remainder** — `S`
  - **Partial quotient** — `T`

  Алгоритм за такт:
  1) `S ← S << 1`
  2) если `A[31]==1`, то `S[0] ← 1`
  3) `A ← A << 1`
  4) если `S >= mem[B]`, то `S ← S - mem[B]`
  5) `T ← T << 1`
  6) если `S >= mem[B]`, то `T[0] ← 1`

  > Пример на Python: см. репозиторий автора (ссылка из оригинала).

- **Left Shift** — `2*` — `( x -- x<<1 )`
- **Right Shift** — `2/` — `( x -- x>>1 )`
- **Invert** — `inv` — `( x -- ~x )`

- **Extend Arithmetic Mode** — `eam` — `( x -- )`  
  Снять верх стека и записать в флаг `EAM` (`0` — выкл., `!=0` — вкл.).

### Побитовые операции
- **AND** — `and` — `( a b -- a&b )`
- **XOR** — `xor` — `( a b -- a^b )`

### Манипуляции со стеком
- **Drop** — `drop` — `( x -- )` — удалить верх стека.
- **Dup** — `dup` — `( x -- x x )` — продублировать верх стека; **не меняет `C`**.
- **Over** — `over` — **в этой ISA эквивалент обмена** двух верхних элементов: `( a b -- b a )`.  
  Операции из спецификации: `T ← pop(); S ← pop(); push(T); push(S)`.
  > ⚠️ Примечание: в классическом Forth `OVER` означает «дублировать второй элемент» `( a b -- a b a )`, а обмен — это `SWAP`. В F32a используется имя `over` для операции обмена — учитывайте это различие.

### Управление потоком
- **Return** — `;` — возврат из подпрограммы: `p ← returnStack.pop()`.
- **Call** — `<label>` — вызов подпрограммы: `returnStack.push(p); p ← <label>`.
- **Jump** — `<label> ;` — безусловный переход: `p ← <label>`.
- **Next** — `next <label>` — цикл по счётчику `R`: `if R != 0 then R ← R - 1; p ← <label>`.
- **If** — `if <label>` — условный переход, если верх стека равен нулю: `if pop()==0 then p ← <label>`.
- **Minus If** — `-if <label>` — переход, если верх стека **неотрицателен**: `if pop() >= 0 then p ← <label>`.
- **Halt** — `halt` — остановка машины.

### Работа с регистрами возврата/данных
- **R→T (RIntoT)** — `r>` — `( -- x )` — снять вершину стека возвратов и положить на стек данных.
- **T→R (TIntoR)** — `>r` — `( x -- )` — перенести вершину стека данных на стек возвратов.

### Остановка
- **halt** — завершить выполнение.

## Идиомы и шаблоны (форто‑подобные)
- **Константа:** `lit 123` `( -- 123 )`.
- **Доступ к массиву по `A` с авто‑инкрементом:** `@+` читает текущий элемент и двигает `A` вперёд; для записи — `!+`.
- **Сохранение/восстановление счётчика цикла:** `N >r ... next label` — перед циклом положите `N` в `R`.
- **Многоразрядное сложение (carry chain):** включите `EAM` и вызывайте `+` последовательно над младшими → старшим словам; `dup` можно использовать между сложениями, не теряя `C`.
- **Ветвление по нулю:** `if L` прыгает, если условие **ложно** (верх стека 0) — это «обратная логика» относительно многих ISA.

## Примеры программ

### Сумма массива из памяти через A/@+ и !+
```asm
\ Вход: A = base адрес массива, B = адрес для записи суммы, N в вершине стека
\ Выход: по адресу B записана сумма
sum_array:
    lit 0          \ ( N -- N 0 ) acc=0
.loop:
    over           \ ( N acc -- acc N )  ; в этой ISA over=swap
    if .done       \ если N==0 → выход
    over           \ вернуть acc наверх
    @+             \ прочитать элемент *A, A++
    +              \ acc += elem ; C обновлён
    over           \ вернуть N наверх
    lit 1
    -              \ N = N-1  (реализуется как добавление с отрицанием, если есть)
    over           \ снова swap, чтобы сверху был N
    jump .loop ;
.done:
    drop           \ убрать N
    b!             \ записать acc в B (B ← acc)
    halt
```

> Если у вас нет явного вычитания, можно реализовать `x-1` как `x lit -1 +`.

### Цикл for/next по счётчику R
```asm
\ Печатаем N раз значение по адресу в B (псевдовывод через !b)
for_next_demo:
    >r             \ N → R
.loop:
    @b             \ читаем mem[B]
    !b             \ записываем в mem[B] (напр., отдать устройству)
    next .loop     \ R=R-1; если R!=0 → повторить
    ;              \ return
```

### 64‑битное сложение на 32‑битных словах с EAM
```asm
\ Складываем два 64‑битных числа: [lo1, hi1] и [lo2, hi2] в стеке
\ Стек (снизу → вверх): lo1 hi1 lo2 hi2
add_u64:
    lit 1
    eam            \ включить EAM
    +              \ hi2+hi1 (+C_in=0)
    over           \ swap → lo2, (сверху hi‑сумма)
    +              \ lo2+lo1 + перенос от предыдущего сложения
    lit 0
    eam            \ выключить EAM
    \ В результате на стеке две 32‑битные суммы: lo hi
    ;
```

### Пошаговое деление (+/): 32 такта
```asm
\ Делим A (дивиденд) на mem[B] (делитель) восстанавливающим делением.
\ Перед началом: S=0, T=0, A=дивиденд, mem[B]=делитель.
step_div32:
    lit 32 >r
.loop:
    +/             \ выполнить один микрошаг (см. определение)
    next .loop
    ;              \ результат: частное в T, остаток в S
```

### MMIO: мигание регистра устройства
```asm
\ Предположим, что по адресу DEVICE в памяти — 32‑битный регистр GPIO/LED
\ B ← DEVICE; бесконечно инвертируем бит 0 и пишем !b
blink:
    lit DEVICE
    b!
.again:
    @b             \ x = mem[B]
    lit 1
    xor            \ x ^= 1
    !b             \ mem[B] = x
    jump .again ;
```

## Советы и типичные ошибки
1. **Семантика `over`.** В этой ISA `over` — это **обмен** (`swap`), а не «дублировать второй элемент», как в Forth.
2. **Флаг переноса `C`.** Полагайтесь на `C` только сразу после `+`/`dup`. Любая другая инструкция может «потерять» его.
3. **EAM.** Не забудьте явно включить/выключить `EAM` через `eam` (кладите `0/1` на стек перед вызовом `eam`).
4. **Адресный шаг в `@+`/`!+`.** Уточните в своей среде: шаг на **байт** или на **слово**. Это важно для обхода массивов.
5. **Порядок операндов.** Мы используем соглашение `( a b -- a+b )`, где `a` — более глубокий элемент (S), `b` — верх (T). Для некоммутативных операций (если появятся) порядок критичен.
6. **Инициализация перед `+/`.** Убедитесь, что `S=0`, `T=0`, `A=дивиденд`, `mem[B]=делитель`.

## FAQ
**Q: Как сделать беззнаковое многоразрядное сложение?**  
A: Включите `EAM`, начните с младших слов; каждое `+` будет использовать входящий перенос `C`. `dup` можно использовать между сложениями — он сохраняет `C`.

**Q: Как организовать цикл по счётчику?**  
A: Положите счётчик в `R` через `>r`, используйте `next label`.

**Q: Чем `@p` отличается от `@`?**  
A: `@p` читает из **абсолютного** адреса, переданного как аргумент инструкции. `@` читает из адреса, находящегося в регистре `A`.

**Q: Есть ли инструкция `b` для чтения регистра B на стек?**  
A: В данной спецификации — нет. Доступ к памяти по `B` есть (`@b/!b`), а значение `B` можно получить косвенно, если ваша среда поддерживает просмотр состояния (`B:dec/hex`).

**Q: Как закодированы переходы и вызовы?**  
A: По общей схеме: 1 байт опкода + 4 байта целевого адреса/метки. В некоторых ассемблерах вызов может записываться как просто имя метки (как в Forth‑подобных системах) — см. документацию вашей среды.

> ✨ **Подсказка:** начинайте отладку с маленьких слов: проверьте `lit/@/!`, затем `+` и `eam`, после — управляющие конструкции `if/next`. Это даёт быстрый прогресс и ясность по флагам `C`/`EAM`.
